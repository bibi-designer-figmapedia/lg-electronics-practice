# /review-design

**이 스킬은 항상 `design-reviewer` 에이전트를 Agent 도구로 호출한다. 직접 검증하거나 수정하지 않는다.**

## 절차

1. **검증 대상 확정** — 어떤 컴포넌트/변경을 검증하는지, 원래 요청 범위가 무엇이었는지, Figma 노드가 있는지 정리한다. 불명확하면 질문한다.
2. **`design-reviewer` 호출** — Agent 도구로 호출하며 다음을 전달한다:
   - 대상 파일 목록과 원래 요청 문장 (3번 "범위 일치" 판정의 기준)
   - Figma URL/노드 ID (6번 "스크린샷 대조"에 필요 — 없으면 그 항목은 FAIL(검증 불가))
   - 판정 규칙: **하나라도 FAIL이면 전체 FAIL**
3. **판정 그대로 전달** — FAIL을 완화해서 요약하지 않는다. "사소한 문제만 있다"로 바꾸지 않는다.
4. **FAIL이면 반환** — 지정된 담당 에이전트(`figma-implementer` / `component-builder` / `token-guardian`)로 수정을 넘기고, 수정 후 이 스킬을 **다시** 실행한다.

## 완료 선언 조건

`design-reviewer`가 **PASS**를 낸 뒤에만 "완료"라고 말한다. 이것이 원칙 4(미완 종료 차단)의 실행 지점이다.

## 하지 않는 것

- 이 스킬 안에서 코드를 고치지 않는다. `design-reviewer`도 고치지 않는다 — 검증자와 구현자가 같아지면 게이트가 무의미해진다.
- 실행하지 못한 검사를 PASS로 적지 않는다.
- 6항목 중 일부만 돌리고 판정하지 않는다.
