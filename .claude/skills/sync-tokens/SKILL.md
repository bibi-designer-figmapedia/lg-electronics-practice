# /sync-tokens

**이 스킬은 항상 `token-guardian` 에이전트를 Agent 도구로 호출한다. 직접 토큰을 편집하지 않는다.**

## 절차

1. **작업 종류 판별** — 셋 중 무엇인지 확인한다:
   - **동기화**: Figma 변수 → 코드 토큰 (Figma 파일/노드 필요 → 없으면 요청한다)
   - **스캔**: 하드코딩 전수 조사 (`npm run verify:tokens`)
   - **추가**: 특정 값에 대한 토큰 신규 정의
2. **`token-guardian` 호출** — Agent 도구로 호출하며 다음을 전달한다:
   - 작업 종류와 대상(Figma 노드 / 스캔 범위 / 추가할 역할)
   - 편집 범위 제약: **`src/tokens/**` 외 파일 편집 금지**
   - 네이밍 제약: 역할 기반(`--color-accent` ⭕ / `--color-blue-500` ❌)
3. **반환 목록 처리** — 에이전트는 컴포넌트를 고치지 않고 "어떤 값을 어떤 토큰으로 바꿔야 하는지" 목록만 낸다. 그 목록의 실제 적용은 `/new-component`(또는 `/figma-to-code`)로 넘긴다.
4. **검증 확인** — `npm run verify:tokens`가 exit 0인지 확인한다.

## 빠른 스캔

토큰 추가 없이 현재 하드코딩만 보려면 에이전트를 거치지 않고 바로 실행해도 된다:

```bash
npm run verify:tokens
```

## 하지 않는 것

- 이 스킬 안에서 토큰 파일을 직접 편집하지 않는다.
- 컴포넌트 파일을 고치지 않는다 — `token-guardian`의 범위 밖이고, 이 스킬의 범위 밖이다.
- `token-exempt`를 하드코딩 회피 수단으로 제안하지 않는다. 정당한 사유(서브픽셀 보정 등)에만 쓰고, 색상에는 쓰지 않는다.
